After completing uploads, Plangrep processes your files asynchronously. Track progress by polling the job status endpoint.

## Polling

Call `GET /api/open/v1/jobs/{jobId}` at a regular interval and inspect the `job.status` field in the response:

```bash
curl https://plangrep.com/api/open/v1/jobs/job_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Reading progress

Use `job.progress.overall` when it is present. Its `completed`, `total`, `unit`, and `percent` fields describe the current aggregate work unit. A job can move through `preparation`, `normalizing`, `rendering`, `indexing`, and `finalizing`, so do not calculate progress from page counts.

When `overall` is `null`, use the optional `step` counter only as a current-stage indicator. `progress.percent` is `null` in that case. Save `progress.identity`; reset any local progress display when its revision changes. See [Jobs: Processing Units](/concepts/jobs#job-progress) for the complete envelope.

`failedPageCount` stays `0` while work is active, cancelled, or expired. It becomes non-zero only for `completed_with_errors` and `failed`.

### Job status reference

| Status | Terminal? | Description |
|---|---|---|
| `provisioning` | No | Project runtime is starting up |
| `awaiting_uploads` | No | Job created; waiting for file uploads |
| `uploading` | No | Files are being received |
| `preflighting` | No | Validating files, analyzing page families, and reserving credits |
| `blocked_insufficient_credits` | No | Processing paused; add credits to resume |
| `processing` | No | Active processing underway |
| `completed` | **Yes** | All files processed successfully |
| `completed_with_errors` | **Yes** | Processing finished with non-fatal errors |
| `failed` | **Yes** | Processing failed; check `errors` in the result |
| `cancelled` | **Yes** | Job was cancelled by request |
| `expired` | **Yes** | Job expired before processing completed |

Stop polling when you reach any terminal status. Continue polling for all non-terminal statuses.

<Note>
  Poll no faster than every 5 seconds. A recommended interval is every 10–30 seconds to stay well within rate limits.
</Note>

### Polling loop example

```python
import time
import requests

def poll_job(job_id, api_key, timeout=600):
    terminal = {"completed", "completed_with_errors", "failed", "cancelled", "expired"}
    url = f"https://plangrep.com/api/open/v1/jobs/{job_id}"
    headers = {"Authorization": f"Bearer {api_key}"}
    start = time.time()

    while time.time() - start < timeout:
        resp = requests.get(url, headers=headers).json()
        status = resp["job"]["status"]
        print(f"Job status: {status}")
        if status in terminal:
            return resp["job"]
        time.sleep(15)

    raise TimeoutError("Job did not complete in time")
```

## Handling blocked jobs

If a job enters `blocked_insufficient_credits`, processing is paused until you add credits to your account. Once credits are available, resume the job:

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/job_xyz789/resume \
  -H "Authorization: Bearer YOUR_API_KEY"
```

The job will re-enter `preflighting` and then `processing` after a successful resume.

## Cancelling a job

To cancel a job that is still in progress, send a cancellation request:

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/job_xyz789/cancel \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Only jobs in a non-terminal status can be cancelled. The response contains the updated job object with `status` set to `"cancelled"`.

<Note>
  Cancellation may not be immediate if processing is already underway. Poll the job status to confirm the transition to `"cancelled"`.
</Note>
