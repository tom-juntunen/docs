After Plangrep processes your files, you can search extracted sources with explicit modes. Use `semantic` for vector search, `grep` for keyword and boolean prepared-text search, `regex` for regular expressions, or `auto` when an agent should try semantic search first and receive keyword follow-up guidance if the vector index is not ready. Use per-project source search for targeted queries within a single project, or organization-wide project search to find relevant projects and sources across your library.

## Search within a project

Send a `POST` request to `/api/open/v1/projects/{projectId}/source-search` with a natural-language query:

```bash
curl -X POST https://plangrep.com/api/open/v1/projects/proj_abc123/source-search \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "exterior wall insulation R-value",
    "mode": "semantic",
    "maxHits": 10,
    "classification": "specifications"
  }'
```

The response includes a ranked list of matching source records:

```json
{
  "status": "ok",
  "query": "exterior wall insulation R-value",
  "queryMode": "semantic",
  "hitCount": 3,
  "hits": [
    {
      "score": 0.92,
      "snippet": "Exterior walls shall have minimum R-19 insulation...",
      "sourceCatalogUri": "source-catalog://project_specification:section_07210",
      "source": {
        "type": "project_specification",
        "id": "project_specification:section_07210",
        "documentId": "spec_001",
        "sectionNumber": "07 21 00",
        "sectionTitle": "Thermal Insulation"
      }
    }
  ]
}
```

Each hit includes a relevance `score` for semantic search, a `snippet` of matching text, and source metadata. For specification hits, use `source.documentId` as the specification document ID and the section ID encoded in `source.id` or `sourceCatalogUri` with [Get Spec Section](/api-reference/project-reads/get-specification-section) to retrieve full section text and structured evidence. For non-specification hits, you can use `sourceCatalogUri` with [Reading bounded source text](#reading-bounded-source-text).

<Note>
  `mode: "semantic"` returns `409 Conflict` when the vector index is not ready. `mode: "auto"` returns `status: "keyword_search_required"` with next actions so agent clients can issue a focused `grep` or `regex` follow-up.
</Note>

### Search modes

| Mode | Use when |
|---|---|
| `semantic` | You want vector search over source meaning. This is the default for direct Open API calls. |
| `grep` | You want required terms, boolean-style `all` / `any` / `not`, or metadata and prepared-text keyword search. |
| `regex` | You need case-insensitive multiline regular expression search over prepared source text. |
| `auto` | An agent should try semantic search first and receive keyword follow-up guidance if vectors are not ready. |

For grep and regex, `query` can be a plain string or a JSON string with keys such as `all`, `any`, `not`, `regex`, `patterns`, `sourceTypes`, and `query`.

### Source search filters

Narrow your search using any combination of these optional filter fields in the request body:

| Filter | Description |
|---|---|
| `classification` | Restrict to `plans`, `specifications`, `documents`, `addenda`, `mixed`, or `other` |
| `entityTypes` | Limit results to specific entity types |
| `regionKind` | Filter regions by kind (for example `detail`, `keynotes`, `schedule`) |
| `regionFamily` | Filter by region family |
| `placedViewKind` | Filter by placed-view kind |
| `tableKind` | Filter by table kind |
| `partRole` | Filter by source part role |
| `fileName` | Case-insensitive substring match against the original file name |
| `sheetNumber` | Exact sheet number match |
| `pageNumber` | Exact page number match |
| `maxHits` | Maximum number of hits to return (1–50) |

## Search across all organization projects

Use `POST /api/open/v1/projects/search` to run a query across every project in your organization at once:

```bash
curl -X POST https://plangrep.com/api/open/v1/projects/search \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "concrete mix design 5000 psi",
    "sourceSearchMode": "semantic",
    "limit": 10
  }'
```

Pass a `projectIds` array to restrict the search to a specific subset of projects:

```json
{
  "query": "concrete mix design 5000 psi",
  "sourceSearchMode": "grep",
  "limit": 10,
  "projectIds": ["proj_abc123", "proj_def456"]
}
```

The response contains a `projects` array. Each entry includes:

- `project` — the matched project object
- `matchReasons` — an explanation of why this project was surfaced
- `sourceMatches` — the specific source records within the project that matched your query

The response also includes a top-level `warnings` array listing any projects that could not be searched (for example because the index is not yet ready).

## Read bounded source text

To retrieve bounded text for a non-specification source record, pass its `sourceCatalogUri` to the source-text endpoint:

```bash
curl -X POST https://plangrep.com/api/open/v1/projects/proj_abc123/source-text \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sourceCatalogUri": "source-catalog://project_sheet_region:region_204",
    "maxChars": 10000,
    "textKind": "text"
  }'
```

The response includes paginated `text` content. Use `nextCursor` to fetch subsequent pages for long sources.

For specification sources, call `GET /api/open/v1/projects/{projectId}/specifications/{specId}/sections/{sectionId}` instead. Use `source.documentId` as `specId`; use the ID portion after `project_specification:` in `source.id` or `sourceCatalogUri` as `sectionId`. That endpoint returns untruncated section `text`, `textLength`, parts, products, requirements, warnings, and facets.

### `textKind` options

| Value | Description |
|---|---|
| `text` | Plain extracted text |
| `markdown` | Text formatted as Markdown |
| `page_regions` | Structured region data for the page |
| `facet_source_text` | Full source text for a selected specification facet. Use with `facetId` |
| `facet_match_text` | Match-focused text for a selected specification facet. Use with `facetId` |

## Get a project summary

`GET /api/open/v1/projects/{projectId}/summary` returns a high-level snapshot of a project, ideal for displaying project context in dashboards or AI prompts:

```bash
curl https://plangrep.com/api/open/v1/projects/proj_abc123/summary \
  -H "Authorization: Bearer YOUR_API_KEY"
```

The response includes:

| Field | Description |
|---|---|
| `aliases` | Alternative project names detected in the documents |
| `titleCandidates` | Candidate project title strings |
| `keyFiles` | Most significant files identified in the project |
| `detectedDisciplines` | Engineering and architectural disciplines present |
| `counts` | Totals for files, sheets, regions, specifications, docs, and overall |
