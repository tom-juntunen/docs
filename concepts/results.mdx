When a job completes, Plangrep produces a normalized JSON result (schema version `v1`) accessible at the job's `resultUrl` or via GET `/api/open/v1/jobs/{jobId}/result`. This result is the authoritative, immutable snapshot of everything extracted from the uploaded files.

## Fetching the Result

```bash
GET /api/open/v1/jobs/{jobId}/result
Authorization: Bearer {your_api_key}
```

The response is a single JSON object. For large result sets, consider streaming or paginating document sections in your own code after downloading.

---

## Top-Level Result Structure

| Field | Type | Description |
|-------|------|-------------|
| `schemaVersion` | string | Always `v1` |
| `job` | object | Summary of the job that produced this result |
| `usage` | object | Credit and page counts for this job (see [Usage](#usage)) |
| `documents` | array | One `ResultDocument` per uploaded file (see [Documents](#documents)) |
| `evidence` | array | Citable source records extracted from submitted job files (see [Evidence](#evidence)) |
| `warnings` | array | Non-fatal issues encountered during processing |
| `errors` | array | Fatal errors for specific pages or files |
| `generatedAt` | string | ISO 8601 timestamp when this result snapshot was produced |

---

## Documents

Each entry in the `documents` array is a `ResultDocument` representing one uploaded file.

| Field | Type | Description |
|-------|------|-------------|
| `documentId` | string | Unique identifier matching the upload registration |
| `fileName` | string | Original file name as provided at upload |
| `classification` | string | Analyzed file classification: `plans`, `specifications`, `documents`, or `mixed` |
| `contentType` | string | MIME type of the file |
| `fileSize` | number | File size in bytes |
| `status` | string | Processing status for this document |
| `pageCount` | number | Total pages in the file |
| `successfulPageCount` | number | Pages that processed without error |
| `drawingPageCount` | number | Analyzed plan pages billed at the drawing-page rate |
| `documentPageCount` | number | Analyzed specification and document pages billed at the document-page rate |
| `successfulDrawingPageCount` | number | Analyzed plan pages that processed without error |
| `successfulDocumentPageCount` | number | Analyzed specification and document pages that processed without error |
| `error` | object \| null | Document-level error, if any |
| `artifacts` | array | Authenticated links to derived file assets (see [Artifacts](#artifacts)) |
| `sheets` | array | Drawing sheets extracted from this document (see [Sheets](#sheets)) |
| `specifications` | array | Specification sections, omitted when none are present |
| `docs` | array | Document sections, omitted when none are present |

<Note>
  Project specification endpoints are document-level first. Use `GET /api/open/v1/projects/{projectId}/specifications/{specId}/sections` and `GET /api/open/v1/projects/{projectId}/specifications/{specId}/sections/{sectionId}` for current specification section reads.
</Note>

The child arrays reflect extracted evidence rather than the file label. For example, a `mixed` file can contain entries in `sheets`, `specifications`, and `docs` at the same time.

## Sheets

Each `ResultSheet` inside a document's `sheets` array represents a single drawing sheet parsed from a plan set.

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Entity identifier for this sheet |
| `sheetId` | string | Unique identifier for this sheet |
| `sheetNumber` | string | Sheet number as read from the title block (e.g., `A101`) |
| `sheetName` | string | Sheet name or title (e.g., `FIRST FLOOR PLAN`) |
| `pageNumber` | number | 1-based page number within the source document |
| `status` | string | Processing status for this sheet |
| `artifacts` | array | Authenticated links scoped to this sheet (thumbnails, renders, etc.) |

## Evidence

The top-level `evidence` array is a flat, deduplicated collection of all extracted evidence records across the entire job. Each `ResultEvidence` record links an extracted piece of information back to its source location.

### Common fields (all evidence types)

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique evidence record identifier |
| `type` | string | Evidence type, commonly `project_file`, `sheet`, `project_sheet_region`, `project_specification`, or `project_doc` |
| `label` | string | Human-readable label for this evidence item |
| `documentId` | string | Source document identifier |
| `fileName` | string | Source file name |
| `classification` | string | Source document classification |
| `sourceRef` | string | `source-catalog://...` URI; pass this value as `sourceCatalogUri` to source-text reads |
| `sourceCallouts` | array | Parsed callout records when the source includes them |
| `artifacts` | array | Artifact links scoped to this evidence item |
| `text` | string \| null | Inline extracted text when available. For normalized sheet-region evidence, this may be omitted; use `normalizedData` instead. |

### Type-specific fields

| Evidence type | Additional fields |
|---------------|-------------------|
| `project_file` | `documentId`, `fileName` |
| `sheet` | `sheetId`, `sheetNumber`, `sheetName` |
| `project_sheet_region` | `regionId`, `regionKey`, `regionName`, `regionNumber`, `sheetId`, `sheetNumber`, `regionKind`, `regionFamily`, `placedViewKind`, `tableKind`, `partRole`, `normalizedData` |
| `project_specification` | `sectionNumber`, `sectionTitle`, `pageNumber` |
| `project_doc` | `pageNumber`, document labels or section fields when available |

Drawing regions include source classification dimensions:

- **`regionKind`** — the kind of region (e.g., keynote legend, detail, schedule)
- **`regionFamily`** — the broader family for the region
- **`placedViewKind`** — the kind of placed drawing view, when applicable
- **`tableKind`** — the kind of table, when applicable
- **`partRole`** — the role of a source part within its parent source
- **`normalizedData`** — structured region data when Plangrep has normalized a region. Shape varies by region kind, such as sheet title blocks, schedules, legends, and placed views.

## Usage

The `usage` object (type `ResultUsage`) provides an immutable breakdown of how credits were consumed by this job.

| Field | Description |
|-------|-------------|
| `pageCount` | Total pages in submitted job files |
| `drawingPageCount` | Number of analyzed plan pages processed |
| `documentPageCount` | Number of analyzed specification and document pages processed |
| `successfulPageCount` | Total pages that completed without error |
| `successfulDrawingPageCount` | Analyzed plan pages that completed without error |
| `successfulDocumentPageCount` | Analyzed specification and document pages that completed without error |
| `creditsDebited` | Total credits charged for this job |
| `drawingCreditsPerPage` | Rate applied to drawing pages (default: 10) |
| `documentCreditsPerPage` | Rate applied to document pages (default: 1) |

See [Credits](/concepts/credits) for a full explanation of the billing model.

## Artifacts

Artifacts are authenticated links to derived assets Plangrep generates during processing. They appear in result objects and project entity responses. Artifact objects include a canonical `type`, a `url`, and may include `readWith` to tell MCP-aware clients whether to open the artifact as an image or file.

| Artifact type | Description |
|---------------|-------------|
| `artifact` | Generic artifact when a more specific type does not apply |
| `doc_markdown` | Converted document Markdown |
| `doc_pdf` | Converted document PDF |
| `model` | Model or structured machine-readable output |
| `region_crop` | Cropped image of a specific drawing region |
| `region_ocr` | Raw OCR output for a region |
| `region_text` | Plain-text extraction of a region |
| `sheet_pdf` | Derived single-sheet PDF |
| `sheet_render` | Full-resolution rendered image of a sheet |
| `source_file` | Original uploaded source file |
| `specification_file` | Source or derivative PDF for a specification document |
| `thumbnail` | Low-resolution preview image |
| `viewer` | Interactive viewer URL for the sheet or document |

When present, `readWith` is either `plangrep_show_artifact_image` or `plangrep_show_artifact_file`.

### Fetching artifact content

Use the same bearer token to fetch artifact content:

```bash
GET /api/open/v1/jobs/{jobId}/artifact?path={artifact_path}
Authorization: Bearer {your_api_key}
```

For short-lived unauthenticated downloads — for example, to pass a URL to a browser or third-party service — use the download token endpoints to generate a time-limited URL.
