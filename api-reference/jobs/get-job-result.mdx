---
title: "Get a User-Visible Job Result"
sidebarTitle: "Get Result"
description: "GET /api/open/v1/jobs/:jobId/result — returns the normalized Open API result or a public-safe user-visible result envelope."
---

Retrieve the result for a user-visible job. Open API ingestion jobs preserve the existing immutable normalized v1 result, including documents, evidence, usage, warnings, and errors. Workspace uploads, saved runs, and review aggregates return a public-safe envelope containing `schemaVersion`, the normalized `job`, and a public-safe `result` object.

Review-derived results require both `jobs:read` and `reviews:read`. Without `reviews:read`, a review ID returns the normal not-found response. Artifact access remains behind the existing `artifacts:read` artifact routes.

## Authentication

Include your API key as `Authorization: Bearer YOUR_API_KEY` in the request headers.

## Endpoint

```
GET https://plangrep.com/api/open/v1/jobs/{jobId}/result
```

## Path Parameters

<ParamField path="jobId" type="string" required>
  The unique identifier of the user-visible job whose result you want to retrieve.
</ParamField>

## Example Request

```bash
curl --request GET \
  --url https://plangrep.com/api/open/v1/jobs/job_01hy3m8qtn2e5r7k9p0w4x1def/result \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Accept: application/json"
```

## Response Fields

The response has two forms:

- An Open API ingestion job returns the existing normalized v1 result described below.
- A workspace upload, saved run, or review aggregate returns this public-safe envelope. `result` contains only public-safe source result data.

```json
{
  "schemaVersion": "v1",
  "job": {
    "id": "job_01hy3m8qtn2e5r7k9p0w4x1def",
    "source": "workspace",
    "jobType": "agent_execution",
    "jobKind": "saved_run",
    "status": "completed",
    "resultUrl": "/api/open/v1/jobs/job_01hy3m8qtn2e5r7k9p0w4x1def/result"
  },
  "result": {}
}
```

<ResponseField name="schemaVersion" type='"v1"' required>
  Always `"v1"`. Used by consumers to select the correct parsing logic as the schema evolves over time. Present in both response forms.
</ResponseField>

<ResponseField name="job" type="ResultJob" required>
  A concise snapshot of the job that produced this result.

  <Expandable title="ResultJob fields">
    <ResponseField name="id" type="string" required>
      The job ID.
    </ResponseField>

    <ResponseField name="projectId" type="string" required>
      The parent project ID.
    </ResponseField>

    <ResponseField name="status" type="string" required>
      Terminal status of the job (`completed` or `completed_with_errors`).
    </ResponseField>

    <ResponseField name="externalId" type="string | null">
      Client-supplied correlation ID, or `null` if none was provided at creation.
    </ResponseField>

    <ResponseField name="createdAt" type="string" required>
      ISO 8601 timestamp of when the job was created.
    </ResponseField>

    <ResponseField name="completedAt" type="string" required>
      ISO 8601 timestamp of when the job reached its terminal state.
    </ResponseField>

    <ResponseField name="expiresAt" type="string" required>
      ISO 8601 timestamp after which the job and its result are no longer accessible.
    </ResponseField>

    <ResponseField name="resultUrl" type="string">
      API path for this result JSON object.
    </ResponseField>

    <ResponseField name="error" type="object | null">
      Error detail if the job encountered a fatal error, otherwise `null`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="usage" type="ResultUsage" required>
  Aggregate processing metrics for the job.

  <Expandable title="ResultUsage fields">
    <ResponseField name="pageCount" type="integer" required>
      Total pages submitted for processing.
    </ResponseField>

    <ResponseField name="successfulPageCount" type="integer" required>
      Pages that were processed without errors.
    </ResponseField>

    <ResponseField name="drawingPageCount" type="integer" required>
      Total number of analyzed plan pages.
    </ResponseField>

    <ResponseField name="documentPageCount" type="integer" required>
      Total number of analyzed specification and document pages.
    </ResponseField>

    <ResponseField name="successfulDrawingPageCount" type="integer" required>
      Analyzed plan pages that were processed successfully.
    </ResponseField>

    <ResponseField name="successfulDocumentPageCount" type="integer" required>
      Analyzed specification and document pages that were processed successfully.
    </ResponseField>

    <ResponseField name="drawingCreditsPerPage" type="integer" required>
      Credits charged per successfully processed plan page. Default: `10`.
    </ResponseField>

    <ResponseField name="documentCreditsPerPage" type="integer" required>
      Credits charged per successfully processed specification or document page. Default: `1`.
    </ResponseField>

    <ResponseField name="creditsDebited" type="integer" required>
      Total credits debited for this job.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="documents" type="ResultDocument[]" required>
  Array of normalized document objects extracted from the uploaded source files. Each document represents a structured entity (e.g., a door schedule, a specification section, a room data sheet) identified by Plangrep during processing.

  <Expandable title="ResultDocument fields">
    <ResponseField name="id" type="string" required>
      Unique identifier for this document within the result.
    </ResponseField>

    <ResponseField name="type" type="string" required>
      The document or entity type (e.g., `"door_schedule"`, `"spec_section"`, `"room"`).
    </ResponseField>

    <ResponseField name="data" type="object" required>
      The normalized, structured data payload for this document. Shape varies by `type`.
    </ResponseField>

    <ResponseField name="evidenceIds" type="string[]" required>
      IDs of `evidence` entries that support this document's extracted data.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="evidence" type="ResultEvidence[]" required>
  Source-level evidence records linking extracted data back to specific locations in the uploaded files.

  <Expandable title="ResultEvidence fields">
    <ResponseField name="id" type="string" required>
      Unique identifier for this evidence record.
    </ResponseField>

    <ResponseField name="fileName" type="string" required>
      The source file this evidence was found in.
    </ResponseField>

    <ResponseField name="pageNumber" type="integer" required>
      The page number within the source file.
    </ResponseField>

    <ResponseField name="sheetNumber" type="string | null">
      The sheet number if the source page is a drawing sheet, otherwise `null`.
    </ResponseField>

    <ResponseField name="boundingBox" type="object | null">
      Pixel-coordinate bounding box of the region within the page, or `null` if not available.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="warnings" type="ResultWarning[]" required>
  Non-fatal warnings raised during processing (e.g., unreadable pages, unsupported file formats). Empty array when there are no warnings.
</ResponseField>

<ResponseField name="errors" type="ResultError[]" required>
  Page-level or file-level errors that prevented full processing. Present in `completed_with_errors` results. Empty array for fully `completed` jobs.
</ResponseField>

<ResponseField name="generatedAt" type="string" required>
  ISO 8601 timestamp of when this result object was generated.
</ResponseField>

<Note>
  Results are only available for jobs with a status of `completed` or `completed_with_errors`. Calling this endpoint on a job in any other status — including `failed`, `cancelled`, or `expired` — will return an error. Check `job.status` with [Get Job](/api-reference/jobs/get-job) before calling this endpoint.
</Note>
