## Overview

Complete an Open API ingestion job after every accepted registration has either reused verified content or finished its signed R2 upload. Workspace-upload, saved-run, and review aggregate IDs are read-only on the Open API surface and return the normal not-found response from this route. Completion assembles multipart objects, verifies new stored bytes, attaches only verified clean content to logical files, and starts preflight.

New content stays quarantined until Plangrep confirms:

- Authoritative byte count equals registered `fileSize`.
- Authoritative SHA-256 equals registered `sha256`.
- File magic and detected type agree with the declaration.
- SHA-256 does not match the configured known-malware blocklist.

A failed check rejects the content and prevents ingestion. Client hashes and upload tokens are never treated as proof of the stored bytes.

<Tip>
  Always send an `Idempotency-Key`. Retry a lost or timed-out response with the same key and body.
</Tip>

## Endpoint

```http
POST https://plangrep.com/api/open/v1/jobs/{jobId}/uploads/complete
```

## Authentication

```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: YOUR_UNIQUE_COMPLETION_KEY
```

## Path parameters

<ParamField path="jobId" type="string" required>
  The job whose registered documents should be verified and processed.
</ParamField>

## Request headers

<ParamField header="Idempotency-Key" type="string">
  A client-generated key of up to 256 characters. Repeating a successful key returns the prior result without starting processing again.
</ParamField>

## Request body

<ParamField body="documentIds" type="string[]">
  Logical document IDs to process. Include reused, direct PUT, and multipart documents. When omitted, Plangrep selects all registered documents for the job.
</ParamField>

<ParamField body="directUploads" type="array">
  Required transport proof for each new `direct_put` document.

  <ParamField body="directUploads[].documentId" type="string" required>
    The document ID returned by registration.
  </ParamField>

  <ParamField body="directUploads[].uploadToken" type="string" required>
    The matching signed upload token returned by registration.
  </ParamField>
</ParamField>

<ParamField body="multipartUploads" type="array">
  Required assembly data for each new `multipart` document.

  <ParamField body="multipartUploads[].documentId" type="string" required>
    The document ID returned by registration.
  </ParamField>

  <ParamField body="multipartUploads[].multipartUploadId" type="string" required>
    The multipart upload ID returned by registration.
  </ParamField>

  <ParamField body="multipartUploads[].uploadToken" type="string" required>
    The matching signed upload token returned by registration.
  </ParamField>

  <ParamField body="multipartUploads[].parts" type="array" required>
    Every uploaded part in ascending part order.

    <ParamField body="multipartUploads[].parts[].partNumber" type="integer" required>
      The 1-based part number.
    </ParamField>

    <ParamField body="multipartUploads[].parts[].etag" type="string" required>
      The `ETag` response header from that part's PUT request.
    </ParamField>
  </ParamField>
</ParamField>

<ParamField body="failedUploads" type="array">
  Optional client-side failures. Report a failed transport so Plangrep can mark the logical document failed instead of waiting for an upload that will not arrive.
</ParamField>

## Completion rules by registration result

| Registration result | Completion data |
|---|---|
| `status: "reused"` | Add `documentId` only. Do not invent an upload token. |
| `uploadMode: "direct_put"` | Add `documentId` and one matching `directUploads` record. |
| `uploadMode: "multipart"` | Add `documentId` and one matching `multipartUploads` record with every part `ETag`. |
| `status: "skipped"` | Omit it from completion. |

## Example: mixed completion

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/JOB_ID/uploads/complete \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: complete-job-123" \
  -d '{
    "documentIds": ["doc_reused", "doc_direct", "doc_multipart"],
    "directUploads": [
      {
        "documentId": "doc_direct",
        "uploadToken": "DIRECT_UPLOAD_TOKEN"
      }
    ],
    "multipartUploads": [
      {
        "documentId": "doc_multipart",
        "multipartUploadId": "MULTIPART_ID",
        "uploadToken": "MULTIPART_UPLOAD_TOKEN",
        "parts": [
          { "partNumber": 1, "etag": "\"etag-value-1\"" },
          { "partNumber": 2, "etag": "\"etag-value-2\"" }
        ]
      }
    ]
  }'
```

`doc_reused` needs no transport record because its physical content was already verified within the same organization.

## Response

**Status: `202 Accepted`**

<ResponseField name="job" type="object">
  The updated job. It transitions to `preflighting` and then `processing` after verification succeeds.
</ResponseField>

<ResponseField name="idempotent" type="boolean">
  Present as `true` when the response came from a previously successful request with the same idempotency key.
</ResponseField>

```json
{
  "job": {
    "id": "job_01abc123",
    "status": "preflighting"
  }
}
```

## Verification failures

Completion can fail before ingestion with errors such as:

| Error code | Meaning |
|---|---|
| `direct_upload_object_missing` | The signed upload did not create the expected R2 object. |
| `upload_size_mismatch` | Stored bytes do not match the registered byte length. |
| `upload_hash_mismatch` | Authoritative SHA-256 does not match registration. |
| `magic_mismatch` | Stored bytes do not match the declared file format. |
| `malware_hash_blocked` | SHA-256 matches the configured known-malware blocklist. |
| `content_blob_not_verified` | The logical file still points to unverified quarantined content. |

Do not retry completion with changed declarations. Register the intended file again and upload the correct bytes.

## Status transitions

```text
awaiting_uploads → uploading → preflighting → processing → completed
                                             ↘ failed
```

Poll [Get Job](/api-reference/jobs/get-job) to observe terminal status.
