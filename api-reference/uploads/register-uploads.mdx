## Overview

Register every file for an Open API ingestion job before sending bytes. Workspace-upload, saved-run, and review aggregate IDs are read-only on the Open API surface and return the normal not-found response from this route. For each declaration, Plangrep returns one of these results:

- An organization-scoped verified content reference with `status: "reused"` and no byte upload.
- A signed `direct_put` instruction with an enforced SHA-256 checksum header.
- Signed `multipart` instructions for files at or above 32 MiB.
- A `skipped` result when no logical file was accepted.

This is the only Open API endpoint for starting file uploads.

<Note>
  A job accepts up to **100 files** and **10 GB** of declared bytes. Each file can be up to **2 GB**.
</Note>

## Endpoint

```http
POST https://plangrep.com/api/open/v1/jobs/{jobId}/uploads
```

## Authentication

```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

## Path parameters

<ParamField path="jobId" type="string" required>
  The job that will process the logical files.
</ParamField>

## Request body

<ParamField body="files" type="array" required>
  Contains between 1 and 100 file declarations.

  <ParamField body="files[].fileName" type="string" required>
    The original filename, including a supported extension.
  </ParamField>

  <ParamField body="files[].fileSize" type="integer" required>
    The exact non-negative byte length. Fractional and precision-losing values are rejected.
  </ParamField>

  <ParamField body="files[].contentType" type="string" required>
    The declared MIME type. It must agree with the filename extension.
  </ParamField>

  <ParamField body="files[].sha256" type="string" required>
    The 64-character hexadecimal SHA-256 digest of the exact file bytes.
  </ParamField>
</ParamField>

<Warning>
  Calculate SHA-256 before registration. In browsers, hash every file incrementally in a worker. Do not load a large file into one JavaScript or WASM buffer.
</Warning>

Do not send `classification`. Plangrep derives classification from page evidence during preflight.

### Supported file types

| File type | Extensions | Common MIME types |
|---|---|---|
| PDF | `.pdf` | `application/pdf` |
| Images | `.png`, `.jpg`, `.jpeg` | `image/png`, `image/jpeg` |
| Word | `.docx` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| Excel | `.xls`, `.xlsx` | `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| PowerPoint | `.pptx` | `application/vnd.openxmlformats-officedocument.presentationml.presentation` |
| CSV | `.csv` | `text/csv`, `application/csv` |
| Markdown | `.md`, `.markdown` | `text/markdown`, `text/plain` |
| Text | `.txt` | `text/plain` |
| JSON | `.json` | `application/json`, `text/json`, `text/plain` |

## Response

**Status: `201 Created`**

<ResponseField name="job" type="object">
  The updated job. Its status is normally `uploading` after registration.
</ResponseField>

<ResponseField name="uploads" type="array">
  One result per accepted or skipped declaration.

  <ResponseField name="uploads[].documentId" type="string">
    The logical document ID. Include accepted document IDs in completion.
  </ResponseField>

  <ResponseField name="uploads[].status" type="string">
    Present as `reused` when verified bytes can be reused or `skipped` when the declaration was not accepted. New transfers omit this field.
  </ResponseField>

  <ResponseField name="uploads[].contentBlobId" type="string">
    Present for `reused`. Identifies verified physical content within your organization.
  </ResponseField>

  <ResponseField name="uploads[].requiresCompletion" type="boolean">
    Present for `reused`. Include the `documentId` in completion when this job should process the logical file.
  </ResponseField>

  <ResponseField name="uploads[].skippedReason" type="string">
    Present for `skipped`. Do not upload or complete that item.
  </ResponseField>

  <ResponseField name="uploads[].uploadMode" type="string">
    Present for new content. Either `direct_put` or `multipart`.
  </ResponseField>

  <ResponseField name="uploads[].uploadUrl" type="string">
    Present for `direct_put`. PUT the full raw file to this signed URL.
  </ResponseField>

  <ResponseField name="uploads[].uploadHeaders" type="object">
    Headers that must be sent exactly as returned. Direct PUT includes `content-type` and `x-amz-checksum-sha256`.
  </ResponseField>

  <ResponseField name="uploads[].checksumAlgorithm" type="string">
    `SHA256` for signed direct PUT uploads.
  </ResponseField>

  <ResponseField name="uploads[].checksumEnforced" type="boolean">
    `true` when R2 enforces the signed checksum header. Multipart currently returns `false` and is authoritatively hashed after assembly.
  </ResponseField>

  <ResponseField name="uploads[].uploadToken" type="string">
    Present for new content. Return it in the matching completion record.
  </ResponseField>

  <ResponseField name="uploads[].expiresAt" type="string">
    Expiration time for the signed instruction. Re-register after expiry.
  </ResponseField>

  <ResponseField name="uploads[].multipartUploadId" type="string">
    Present for `multipart`. Return it during completion.
  </ResponseField>

  <ResponseField name="uploads[].partSize" type="integer">
    Present for `multipart`. The target part size in bytes.
  </ResponseField>

  <ResponseField name="uploads[].parts" type="array">
    Present for `multipart`. Upload every part.

    <ResponseField name="uploads[].parts[].partNumber" type="integer">
      The 1-based part number.
    </ResponseField>

    <ResponseField name="uploads[].parts[].startByte" type="integer">
      The inclusive local file offset.
    </ResponseField>

    <ResponseField name="uploads[].parts[].endByteExclusive" type="integer">
      The exclusive local file offset.
    </ResponseField>

    <ResponseField name="uploads[].parts[].uploadUrl" type="string">
      The signed PUT URL for this part.
    </ResponseField>

    <ResponseField name="uploads[].parts[].uploadHeaders" type="object">
      Headers to include in the part PUT.
    </ResponseField>
  </ResponseField>
</ResponseField>

## Example request

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/JOB_ID/uploads \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "files": [
      {
        "fileName": "large-drawings.pdf",
        "fileSize": 52428800,
        "contentType": "application/pdf",
        "sha256": "a3f1b2c4d5e6f7081920a1b2c3d4e5f6a7b8c9d0e1f2031415161718191a1b1c"
      }
    ]
  }'
```

## Example response: verified reuse

```json
{
  "job": { "id": "job_01abc123", "status": "uploading" },
  "uploads": [
    {
      "documentId": "doc_01xyz789",
      "contentBlobId": "blob_01verified",
      "fileName": "large-drawings.pdf",
      "fileSize": 52428800,
      "contentType": "application/pdf",
      "sha256": "a3f1b2c4d5e6f7081920a1b2c3d4e5f6a7b8c9d0e1f2031415161718191a1b1c",
      "status": "reused",
      "requiresCompletion": true
    }
  ]
}
```

Send no file bytes for this result. Complete it with `documentIds: ["doc_01xyz789"]`.

## Example response: direct PUT

```json
{
  "job": { "id": "job_01abc123", "status": "uploading" },
  "uploads": [
    {
      "documentId": "doc_01xyz789",
      "uploadMode": "direct_put",
      "uploadUrl": "https://ACCOUNT.r2.cloudflarestorage.com/BUCKET/OBJECT?X-Amz-...",
      "uploadHeaders": {
        "content-type": "application/pdf",
        "x-amz-checksum-sha256": "BASE64_SHA256_CHECKSUM"
      },
      "checksumAlgorithm": "SHA256",
      "checksumEnforced": true,
      "uploadToken": "UPLOAD_TOKEN",
      "expiresAt": "2026-07-14T18:30:00Z"
    }
  ]
}
```

PUT the complete file with every returned header, then complete it with `{ documentId, uploadToken }` in `directUploads`.

## Example response: multipart

```json
{
  "job": { "id": "job_01abc123", "status": "uploading" },
  "uploads": [
    {
      "documentId": "doc_01xyz789",
      "uploadMode": "multipart",
      "multipartUploadId": "MULTIPART_ID",
      "partSize": 33554432,
      "checksumEnforced": false,
      "uploadToken": "UPLOAD_TOKEN",
      "expiresAt": "2026-07-14T18:30:00Z",
      "parts": [
        {
          "partNumber": 1,
          "startByte": 0,
          "endByteExclusive": 33554432,
          "uploadUrl": "https://ACCOUNT.r2.cloudflarestorage.com/BUCKET/OBJECT?partNumber=1&...",
          "uploadHeaders": {}
        },
        {
          "partNumber": 2,
          "startByte": 33554432,
          "endByteExclusive": 52428800,
          "uploadUrl": "https://ACCOUNT.r2.cloudflarestorage.com/BUCKET/OBJECT?partNumber=2&...",
          "uploadHeaders": {}
        }
      ]
    }
  ]
}
```

Upload every range, record each response `ETag`, and return the part list in `multipartUploads`.
