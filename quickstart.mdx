This guide walks through the canonical Open API flow for one PDF: create a project and job, calculate the file's SHA-256, register it, follow the returned upload instruction, complete verification, and fetch the result.

## Prerequisites

- A Plangrep account
- An API key — see [Authentication](/authentication)
- A PDF file named `drawings.pdf`
- `curl`, `shasum`, and `wc`

<Steps>

<Step title="Create a project">

```bash
curl -X POST https://plangrep.com/api/open/v1/projects \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: create-first-project" \
  -d '{ "name": "My First Project" }'
```

The response has `202 Accepted` and starts with `project.status: "provisioning"`. Poll the project every 10 seconds until its status is `"ready"`:

```bash
curl https://plangrep.com/api/open/v1/projects/proj_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

</Step>

<Step title="Create a job">

```bash
curl -X POST https://plangrep.com/api/open/v1/projects/proj_abc123/jobs \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: create-first-job" \
  -d '{}'
```

Save the returned job ID. A new job has `status: "awaiting_uploads"`.

</Step>

<Step title="Hash and register the file">

Calculate the exact byte length and SHA-256 before you send file bytes:

```bash
FILE_SIZE=$(wc -c < drawings.pdf | tr -d ' ')
FILE_SHA256=$(shasum -a 256 drawings.pdf | awk '{print $1}')
```

Register all four required declarations:

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/job_xyz789/uploads \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"files\":[{\"fileName\":\"drawings.pdf\",\"fileSize\":${FILE_SIZE},\"contentType\":\"application/pdf\",\"sha256\":\"${FILE_SHA256}\"}]}"
```

Registration returns one item in `uploads`. Save its `documentId` and follow the returned branch:

- `status: "reused"` means Plangrep already has matching verified content in your organization. Skip the byte upload.
- `uploadMode: "direct_put"` returns one `uploadUrl`, exact `uploadHeaders`, and an `uploadToken`.
- `uploadMode: "multipart"` returns signed part URLs. See [Hash-first, verified file uploads](/concepts/uploads).

</Step>

<Step title="Upload new bytes directly">

For `direct_put`, PUT the raw file to `uploadUrl`. Include every header from `uploadHeaders` without changing its value:

```bash
curl -X PUT "UPLOAD_URL_FROM_REGISTRATION" \
  -H "content-type: application/pdf" \
  -H "x-amz-checksum-sha256: BASE64_CHECKSUM_FROM_UPLOAD_HEADERS" \
  --data-binary @drawings.pdf
```

The checksum header is signed into the URL. Do not replace its base64 value with the hexadecimal digest.

If registration returned `status: "reused"`, do not make this PUT request.

</Step>

<Step title="Complete verification and start processing">

For a direct PUT, return the document ID and upload token:

```bash
curl -X POST https://plangrep.com/api/open/v1/jobs/job_xyz789/uploads/complete \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: complete-first-job" \
  -d '{
    "documentIds": ["doc_abc123"],
    "directUploads": [
      { "documentId": "doc_abc123", "uploadToken": "UPLOAD_TOKEN" }
    ]
  }'
```

For reused content, send only its document ID:

```json
{ "documentIds": ["doc_abc123"] }
```

During completion, Plangrep streams the stored object and verifies its authoritative size, SHA-256, file magic/type, and known-malware hash status. Only verified content is attached to the logical file and sent to ingestion. The response has `202 Accepted` and the job transitions to `preflighting`.

</Step>

<Step title="Poll for completion">

```bash
curl https://plangrep.com/api/open/v1/jobs/job_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Continue until `job.status` is `completed`, `completed_with_errors`, `failed`, `cancelled`, or `expired`.

| Status | Description |
|---|---|
| `awaiting_uploads` | Ready for file registration |
| `uploading` | Waiting for direct uploads and completion |
| `preflighting` | Verifying and analyzing registered files, then reserving credits |
| `blocked_insufficient_credits` | Paused until your organization adds credits |
| `processing` | Extracting and normalizing data |
| `completed` | All documents processed successfully |
| `completed_with_errors` | Processing finished with one or more document errors |
| `failed` | The job failed and cannot continue |

</Step>

<Step title="Fetch results">

```bash
curl https://plangrep.com/api/open/v1/jobs/job_xyz789/result \
  -H "Authorization: Bearer YOUR_API_KEY"
```

The result contains job and usage summaries, normalized documents, source-backed evidence, warnings, and errors.

</Step>

</Steps>
